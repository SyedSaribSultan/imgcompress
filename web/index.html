Quality is measured, not guessed

Most compressors ask you to pick a quality number and hope. This one encodes each image several different ways, decodes every candidate back, scores it against the original, and keeps the smallest file that still clears the floor you set. Then it shows you the evidence.

1

Encode it several ways

mozjpeg, palette PNG, lossless PNG — plus WebP and AVIF if you allow them. Each format is searched independently for the lowest setting that still clears your floor, and every PNG gets a lossless oxipng squeeze.

2

Score every candidate

Each encode is decoded back and compared to the original with SSIM at the 5th percentile, so a big flat background can't hide a damaged subject. Transparency is scored on dark and light backdrops. The shipped file is verified per colour channel too.

3

Keep the smallest that passes

The winner is whichever candidate came out smallest while still passing — and nothing bigger than your original is ever produced. Already-tiny files pass through untouched.

The format is a bake-off, not an assumption

Which format wins is genuinely content-dependent — measured on the project's benchmark corpus, with up to a 40× spread between the best and worst choice for the same image:

Why the default target is Figma, not WebP

"Just use WebP" is the standard advice, and it's wrong if your images are going into Figma. Figma's plugin API only knows PNG, JPEG and GIF, and the standing community answer is that a WebP dropped onto the canvas is decoded and re-encoded as PNG — turning your beautifully compressed 40 KB WebP into a multi-megabyte PNG inside the .fig. The Figma target therefore sticks to formats Figma stores byte-for-byte, and caps dimensions at 4096px — beyond that, Figma rescales destructively on import. Pick the web for anything not bound for Figma.

Want more? The desktop version goes further

This page ships mozjpeg, oxipng and AVIF compiled to WebAssembly — the same class of encoders the professionals use, running locally in your browser. The Python version still has a few things a browser can't offer:

  • SSIMULACRA 2 — the metric the image-compression community converged on (r≈0.88 against human judgement; the web version uses per-channel SSIM at the 5th percentile)
  • libimagequant — the engine inside pngquant, still ahead of any in-browser quantizer on photographic palettes
  • zopfli — a slower, slightly deeper cousin of oxipng
  • Folder watching — point it at your Figma export folder and new arrivals are compressed as they land
  • Batch saves to disk — no downloads folder, no zips

Questions

Is anything uploaded?

No. Compression runs entirely in your browser using Web Workers and WebAssembly. Images never leave your device, and the page makes no network requests after it loads. There are no cookies and no analytics.

Why does it default to JPEG and PNG instead of WebP?

The default target is Figma. Figma's plugin API only accepts PNG, JPEG and GIF, and the standing community answer is that WebP uploads are decoded and re-encoded as PNG on import — turning a small WebP into a large PNG inside the .fig file. Switch the target to the web to allow WebP and AVIF output.

How is quality measured?

Every candidate encode is decoded back and compared to the original with SSIM, aggregated at the 5th percentile so a large flat background cannot hide a damaged region. Transparent images are scored over a dark and a light backdrop, and the worse score wins. The encode that ships is also verified per colour channel, because luma-only metrics are blind to chroma damage.

What is the difference between this and the desktop version?

The web version runs mozjpeg, oxipng and AVIF as WebAssembly and scores with per-channel SSIM. The desktop version (pip install imgcompress) adds SSIMULACRA 2 — the stronger perceptual metric — plus libimagequant and zopfli, can watch folders, and saves batches straight to disk.

Which formats can it read and write?

It reads PNG, JPEG, WebP, BMP and GIF in every modern browser, and TIFF where the browser can decode it. Animated GIFs are passed through untouched. Output is JPEG, palette PNG, lossless PNG, WebP or AVIF (AVIF on the web target, where the browser supports it).

Is it free?

Yes — free and open source under the MIT licence. The code is on GitHub.
