imgcompress
Compress an image

Images 70–90% smaller, on your own machine

Every image comes out as small as it can go without you being able to see the difference — and you get the side by side to check that for yourself. Each one is saved several different ways, every version is compared to your original, and the smallest one that still looks close enough is the one you keep. It is free, it is open source, and no image ever leaves your computer.

What your computer will say the first time

These builds are not signed. A signing certificate is a yearly bill this project does not carry, and a signature is a receipt for who built something rather than proof that it is safe — but your computer cannot tell the difference, so it will interrupt you once, in language that sounds worse than what is going on. Here is exactly what you will see.

Windows: “Windows protected your PC”

A blue window from Microsoft Defender SmartScreen, with a Don't run button and apparently no other way out.

  1. Click More info, the small line under the message.
  2. Click Run anyway, which appears once you do.

SmartScreen shows this for any program it has not yet seen enough people run. It is a reputation count, not a verdict, and it stops appearing on its own once a build has been downloaded enough times.

macOS: “Apple could not verify” it

Recent versions say Apple could not verify the app is free of malware; older ones say it cannot be opened because the developer cannot be verified. Same thing: the app is not signed and notarised.

  1. In Finder, Control-click (or right-click) the app and choose Open — then Open again in the dialog that follows.
  2. On macOS 15 Sequoia and newer, that shortcut is gone. Open System Settings → Privacy & Security, scroll down to the Security section, and click Open Anyway next to the message naming the app.

Either way you are asked once, and never again for that copy.

If you would rather not do any of that, both of the other routes skip it entirely: the browser version installs nothing at all, and a pip install is not something the operating system gates.

What the app adds over the browser version

The two compress to the same measured standard with the same class of encoders — the comparison holds both of them, and everything else, to it row by row. What the app adds is workflow:

  • Folder watching — point it at your export folder and new arrivals are compressed as they land
  • A whole batch straight to disk — no downloads folder to sort out, no zip to unpack
  • A scriptable command line — for build steps, CI, and anything you would rather not do by hand twice
  • Two more engines — libimagequant and zopfli, worth a few percent on flat artwork with only a handful of colours

That is the whole of the difference. On photographs and screenshots the two hand you the same file, so if none of the above is something you need, the browser version is not a cut-down edition — it is the same tool without the install.

The evidence, before you install anything

A size claim means nothing on its own, because anything can be made smaller by making it look worse. So on the comparison page every strategy — this tool, single-format pipelines, and the quality settings people normally reach for — was searched for the smallest file that still looks close enough to the original, all of them held to the same visual match of 90 out of 100. It includes the one image where the browser version loses to the app, because leaving that out would make the rest worth less.

Or install it with pip

If you already have Python 3.9 or newer, this is the shortest way in — and on Linux it is the only one:

pip install "imgcompress[full,app]"
imgcompress-gui            # the app
imgcompress photos/        # or the command line

The extras pull in the parts that do the real work: the perceptual measure, libimagequant and zopfli. All of them ship prebuilt wheels for Windows, so there is nothing to compile and no binaries to chase. imgcompress --check prints which engines came out active on your machine.
